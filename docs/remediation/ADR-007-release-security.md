# ADR-007: согласованная выдача и фактический токеновый бюджет

Статус: принято для single-process MVP. Дата: 20.10.2026.

Причина: F01 позволял вернуть evidence из предыдущего состояния ACL; F02 допускал контекст больше окна Qwen. Разделение Control/Data Plane и LangGraph сохраняется.

Авторизация финального результата выполняется в `Store.finalize` под `BEGIN IMMEDIATE`. Чанки, версия/текст/tenant/title/page, граф, session ownership, history и итоговая audit-запись согласованы в одной SQL-транзакции. Ответ полностью сериализуется до commit. Решение действительно относительно этого snapshot и commit: SQL-администратор, зафиксировавший отзыв раньше, наблюдается; конкурентный writer после захвата write reservation завершается после commit выдачи. Уже авторизованные для отправки/переданные байты отозвать невозможно. SSE выпускает один целый проверенный результат с той же границей, не отдельные токены.

Транзакция не охватывает inference и сетевую передачу. История не сохраняет цитат. Предварительное audit-событие `pending_release` содержит только псевдоним/статус, без source IDs и текста; успешные source IDs пишутся только после финальной авторизации. Identity provisioning повторно проверяется по digest токена; файловая identity snapshot не является распределённой OIDC-транзакцией. Атомарный provisioning-файл и однопроцессный runtime — ограничения MVP.

Альтернативы: повторный `allowed()` без транзакции сохраняет окно; длительный lock на время LLM блокирует администрирование; PostgreSQL/OIDC lease пригодны для нескольких реплик, но сейчас меняли бы работающий стек. `security_epoch` изменяется триггерами при изменениях документов/ACL/графа и идентифицирует snapshot. Результаты ещё раз сверяются с актуальными чанками независимо от epoch.

Бюджетирование использует `/tokenize` того же локального vLLM: фактический tokenizer, chat template и `add_generation_prompt`. Сообщения строятся одной функцией для подсчёта и generation; память представлена разрешёнными источниками, отдельного небюджетированного history prompt нет. Учитываются system, question, JSON источников, output reserve и safety margin. Конфигурация backend не должна превышать серверный limit. Неверный ответ tokenizer приводит к fail-closed 503; слишком большой вопрос — 422. Чанки пакуются целиком, по приоритету, без усечения слов/отрицаний. Если весь GraphRAG context не помещается, возвращаются исходные полные extractive-цитаты с явным `extractive-context-limited`, без нейросетевой генерации.

Trade-offs: дополнительные локальные tokenize HTTP calls и короткая сериализованная SQL-транзакция; меньше throughput, чем небезопасная выдача из stale state. Защита смысла цитат и quality evaluation имеют собственные проверки и не следуют автоматически из точного подсчёта токенов.
