# Нагрузочный отчёт

## Оборудование и конфигурация

NVIDIA GeForce RTX 4070, 12 GiB VRAM; 28 доступных CPU-потоков, 32 GiB RAM. Windows 11, Docker Desktop с WSL2. Одна API-реплика, SQLite, Qdrant и Neo4j, локальный vLLM 0.10.2.

Модель Qwen2.5-7B-Instruct-AWQ, AWQ Marlin, half. Контекст 4096, max-num-seqs 4, max-num-batched-tokens 1024, gpu-memory-utilization 0,80, prefix caching включён. Temperature 0, лимит ответа 700 токенов. Модель выбирает source IDs; сервер восстанавливает точные цитаты.

## Методика

HTTP-клиент обращается через Nginx gateway к backend. Четыре параллельных запроса, перед измерением восемь запросов для прогрева. Вопрос: «Как связан насос Н-17 с датчиком Д-8?». Корпус содержит три синтетических документа, пользователь engineer-b. Запросы повторяют один вопрос; в ответах используется реальный vLLM. Для этого вопроса модель обрабатывает 415 входных и 18 выходных токенов. Во время измерения сборки и функциональные тесты не выполняются.

## Результаты

| Запросов | Параллельность | RPS | p50, мс | p95, мс | p99, мс | HTTP-ошибок |
|---|---|---|---|---|---|---|
| 48 | 4 | 8,66 | 428,39 | 690,80 | 728,64 | 0 |
| 192 | 4 | 9,32 | 416,92 | 468,75 | 834,10 | 0 |

RPS рассчитывается по успешно завершённым HTTP-запросам. Задержка включает gateway, авторизацию, retrieval, обход графа, генерацию, проверку цитат и формирование ответа.

## Область применимости

Результаты характеризуют короткий тёплый workload с повторяющимся вопросом и prefix cache. Они не определяют пропускную способность на большом разнородном корпусе, холодном кеше или длительной нагрузке. Для другой модели, длины контекста, оборудования и количества пользователей нужны отдельные измерения.

Воспроизведение в настроенном контейнерном профиле: `python tools/measure_http.py --requests 192 --concurrency 4 --output data/benchmark.json`. Перед измерением выполните восемь запросов прогрева. Для in-process CPU-измерения предусмотрен `python -m backend.benchmark`; его результаты относятся к extractive ASGI-профилю и имеют отдельный scope.
