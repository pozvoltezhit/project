# Эксплуатация

## dependencies

Проверьте `docker compose -f infra/compose.yaml ps`, /health и /ready. Для профилей индексов и GPU добавляйте соответствующие compose-файлы ко всем командам. /ready сообщает о недоступных обязательных зависимостях. Веса модели должны быть подготовлены до запуска. Порты сервисов доступны через loopback; ключи и пароли хранятся в локальном data/.

## errors

По request ID найдите trace в Jaeger и сообщения backend. Проверьте доступность SQL, индексов и vLLM. Не помещайте тексты закрытых документов и ключи в общие журналы. Ответы 401/403 проверяйте по provisioning и grants, 429 - по очереди и лимитам нагрузки.

## latency

Сопоставьте задержки agent stages и llm.generate с HTTP histogram, очередью vLLM и использованием GPU. Отделяйте холодный запуск от прогретого workload. Методика измерения приведена в PERFORMANCE.md.

## budget

Проверьте длину вопроса, число найденных источников, контекст и резерв ответа. Полные фрагменты не обрезаются ради прохождения лимита; режим fallback указан в usage.mode.

## evaluation

Выполните `python -m backend.evaluate --output data/eval-report.json`. Для реальной модели используйте внутренний LLM_URL и --gpu. Неполный набор или неверная цитата требуют проверки источников и тестового случая. Изменения корпуса, модели и prompt проверяйте повторно.

## telemetry

Проверьте OTLP endpoint, scrape targets Prometheus и datasource Grafana. Тексты вопросов, ответов и документов не должны появляться в trace attributes. Диагностика не должна открывать DB-порты наружу.

## Индексы и восстановление

После изменения документов/ACL выполните `python -m backend.index_admin build`, затем status и /ready внутри настроенного backend. Для справки по rollback и очистке версий используйте `python -m backend.index_admin --help`.

Перед обслуживанием создайте согласованный SQL backup средствами `python -m backend.backup --help`. Сохраняйте grants, версии источников, identities и конфигурацию модели отдельно от производных индексов. Восстановление сначала проверяйте в отдельном каталоге данных, затем перестраивайте индексы и проверяйте доступ двух пользователей. Не подменяйте рабочую БД непроверенной копией.
